1. Diagnostic de production

Paramètres préremplis pour ton installation. Lecture seule.

2. Sauvegarde cohérente

Bases PostgreSQL, données et filestore, configuration, code des modules et système de fichiers du conteneur.

Odoo 12 sera arrêté pendant la capture, puis redémarré. PostgreSQL reste actif. Prévoir une période où personne n’utilise Odoo.

Aucune sauvegarde.

3. Préparer l’étape suivante

Migration 12 → 13

Télécharge OpenUpgrade, fige les commits et construit l’image Docker. Cette opération peut prendre plusieurs minutes. Internet requis sur le serveur.

Modules tiers adaptés à la version cible : . Les modules Odoo 12 ne sont pas réutilisés automatiquement.

4. Migrer la copie

Restauration réelle du point de contrôle, comparaison des compteurs, neutralisation des courriels et tâches planifiées, puis exécution d’OpenUpgrade sur un réseau Docker isolé.

Décisions pour les modules absents

Un module absent bloque l’étape. Documenter une prise en charge par OpenUpgrade, ou un renommage/fusion avec scripts adaptés. Aucune désinstallation automatique. Les décisions « openupgrade » doivent être appuyées par le code ou la documentation OCA.

Exemple : {"ancien_module":{"action":"openupgrade","evidence":"URL et script OCA vérifiés pour cette version"}}. À partir de 14 : actions rename ou merge avec target et evidence.

En cas d’erreur, le dernier point validé est conservé. La relance crée un nouvel essai.

5. Contrôler et valider

La comparaison apparaîtra après la première migration.
Ouvrir Odoo de test

Tunnel SSH vers 18069 nécessaire depuis un autre ordinateur. Comptes et mots de passe identiques à la copie. Les intégrations externes restent isolées du réseau.

La validation ferme la copie de test et sauvegarde la base avec son filestore. Elle ne remplace pas la production. Après 19, le basculement de production reste une opération distincte.

Journal des opérations
